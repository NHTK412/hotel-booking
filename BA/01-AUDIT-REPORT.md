### 1.2 Bối cảnh & Mục tiêu Nâng cấp (Context & Objectives)

Hệ thống **Hotel Booking** hiện tại (`v1.0`) được phát triển ở quy mô đồ án môn học gồm 3 thành phần: Backend Java Spring Boot (`hotel-booking-be`), Web Portal React (`hotel-booking-fe`) và Mobile App Flutter (`hotel-booking-app`). Mục tiêu của đợt kiểm toán này là đánh giá trung thực, dựa trên bằng chứng mã nguồn thực tế (code-level evidence), nhằm làm rõ toàn bộ lỗ hổng bảo mật, lỗi logic nghiệp vụ cốt lõi, điểm gãy giao ước liên tầng (Cross-Layer Contract Mismatch) và nợ kỹ thuật trước khi nâng cấp lên phiên bản **`v2.0` chuẩn Production-Ready phục vụ hồ sơ năng lực (CV / Portfolio)**.

Các định hướng mục tiêu đã được phê duyệt cho phiên bản `v2.0`:
- **Phạm vi trong dự án (In-Scope)**: Nâng cấp toàn diện **Backend (`hotel-booking-be`)** theo kiến trúc **Modular Monolith + Spring Internal Domain Events + Redis + MinIO + Flyway**; hoàn thiện **Web Management Portal (`hotel-booking-fe`)** đa vai trò (`ADMIN`, `HOST/MANAGER`, `RECEPTIONIST`) với TypeScript + TanStack Query + React Hook Form/Zod; đồng bộ & tái cấu trúc **Mobile App (`hotel-booking-app`)** cho vai trò `CUSTOMER`.
- **Phạm vi ngoài dự án (Out-of-Scope — Phase 2)**: Giao diện đặt phòng cho khách vãng lai (Guest Booking) trên Web Portal, Đặt nhiều phòng trong cùng một đơn (Multi-room Booking), Giá động theo mùa/cuối tuần (Dynamic/Seasonal Pricing), và tích hợp trực tiếp thêm VNPay/Stripe (nhưng thiết kế sẵn **Payment Strategy/Adapter Pattern** trên nền ZaloPay Sandbox).
- **Chuyển đổi Lưu trữ Đối tượng (Object Storage Migration)**: Thay thế hoàn toàn dịch vụ bên thứ ba Cloudinary (v1.0) sang **MinIO (S3-compatible Object Storage)** tự chủ qua Docker Compose nhằm giải quyết dứt điểm lỗi gãy ảnh liên tầng 3 lớp, lỗi tự động xóa ảnh bìa và loại bỏ rò rỉ khóa bí mật ra ngoài.

> [!CAUTION]
> **ĐÁNH GIÁ RỦI RO TỔNG THỂ (OVERALL RISK RATING): CRITICAL (KHÔNG ĐẠT CHUẨN PRODUCTION / CV)**
> Ở hiện trạng `v1.0`, hệ thống **không thể đưa vào vận hành thực tế hoặc dùng làm dự án mẫu phỏng vấn kỹ thuật** do tồn tại đồng thời 5 nhóm rủi ro chặn phát hành (Release Blockers):
> 1. **Lộ bí mật thực & Chiếm quyền tài khoản (Credential Leaks & Account Takeover)**: Mật khẩu ứng dụng Gmail, Cloudinary secret, JWT fallback và Google Maps API Key đang nằm công khai trong Git; lỗ hổng OAuth bypass chữ ký và OTP 4 số không giới hạn thử sai cho phép chiếm đoạt bất kỳ tài khoản Customer, Host hoặc Admin nào.
> 2. **Đặt trùng phòng & Sai lệch tài chính (Overbooking & Financial Corruption)**: Lỗi tranh chấp TOCTOU trong `BookingService`, đảo ngược giờ check-in/check-out (`12:00`/`14:00`), thiếu Idempotency/kiểm tra Late Webhook ở ZaloPay và xung đột đơn vị `discount` (VNĐ vs %) có thể tạo đơn đặt trùng xác nhận hoặc tính ra giá âm.
> 3. **Đứt gãy giao ước liên tầng (Broken 3-Layer Contracts)**: Web FE gọi sai 4 API cốt lõi (`404`/`405`) và hỏng nhánh `master`; Mobile App gọi endpoint upload ảnh đã bị xóa (`404`) và nối sai đường dẫn ảnh ở 8/9 màn hình; Pagination lệch hoàn toàn giữa 3 lớp.
> 4. **Phân quyền RBAC & IDOR lỏng lẻo**: Người dùng thường có thể đọc PII toàn bộ tài khoản khác (`GET /api/users/{userId}`), tạo đơn thanh toán cho booking của người khác, trong khi `ROLE_RECEPTIONIST` và nhân viên bị khóa (`INACTIVE`) vẫn thao tác toàn quyền quản trị khách sạn.
> 5. **Độ tin cậy kiểm thử & vận hành thấp**: Kiểm thử Concurrency của Backend dùng giả lập Mockito (không chạm DB/Hibernate thật), Integration Test bỏ qua SecurityFilterChain; Web FE và Mobile App có **0% Test Coverage**; Docker Compose bị lỗi khởi động do thiếu mount khóa Firebase JSON và `application-prod.properties` bật `ddl-auto=update`.

## 2. Đánh giá Kiến trúc & Hiện trạng 3 Thành phần (As-Is Architecture Assessment)

### 2.1 Backend (`hotel-booking-be`)

#### A. Công nghệ & Kiến trúc Hiện tại (Current Tech Stack & Architecture)
- **Kiến trúc**: Layered Monolith (`controller → service → repository → model`), `server.servlet.context-path=/api`, kích hoạt `@EnableScheduling` và `@EnableJpaAuditing` (`HotelbookingApplication.java`). Chưa phân tách biên giới module (Modular Boundaries), chưa bật `@EnableCaching`, `@EnableAsync`, chưa tích hợp Flyway/Liquibase, Spring Boot Actuator, Structured Logging hay CI/CD.
- **Ngăn xếp công nghệ (`pom.xml`)**: Java 21, Spring Boot `4.0.0`, Spring Security + JWT (`jjwt 0.11.5`, HS256), Spring Data JPA / Hibernate (`ddl-auto=update`), MySQL `8.0`, Redis `7` (`spring-boot-starter-data-redis` — chỉ dùng lưu OTP và Refresh Token, **không dùng làm Cache hay Rate Limiter**), `spring-boot-starter-validation`, `spring-boot-starter-mail` (Gmail SMTP), `springdoc-openapi-starter-webmvc-ui:2.8.13`, `firebase-admin:9.4.2` (FCM & OAuth), `cloudinary-http44:1.39.0` (lưu trữ ảnh hiện tại v1.0), `com.github.davidmoten:geo:0.7.7` (GeoHash), `httpclient:4.5.14` (HTTP client đời cũ cho ZaloPay), `org.json:20240303`.
- **Hạ tầng & Docker (`Dockerfile`, `docker-compose.yml`)**: Multi-stage `Dockerfile` (Temurin 21 Alpine, user non-root `spring`), `docker-compose.yml` gồm 3 container (`mysql:8.0`, `redis:7-alpine`, `backend`). **Lỗi vận hành**: Không copy/mount tệp Firebase service account JSON nên `FirebaseConfig.@PostConstruct` gây crash ngay khi khởi động container; chưa có container **MinIO**.

#### B. Tổng quan Thực thể CSDL & Endpoints (Database Entities & API Inventory)
- **12 Entities (`model/`)**:
  - Kế thừa `BaseEntity` (`createAt`, `updateAt`): `Users`, `UserAuthProvider`, `Accommodations` (kèm bảng nối `Accommodations_UserFavorites`), `AccommodationStaff`, `locations`, `RoomTypes` (kèm `@ElementCollection` `roomImagesPreview`, `roomAmenities`), `Rooms` (có `@Version`), `Bookings`, `Payments`, `Reviews`.
  - Không kế thừa `BaseEntity`: `device`, `UploadedFile`.
  - **Thiếu hoàn toàn ở v1.0**: `Voucher/Promotion`, `Refund`, `Notification` (chỉ đẩy FCM không lưu lịch sử DB), `AuditLog`, `ShedLock`.
- **10 Controllers (~54 endpoints dưới `/api`)**:
  - `AuthController` (`/auth`): 8 endpoints (`login`, `oauth`, `register`, `send-otp`, `verify-otp`, `reset-password`, `refresh-token`, `logout`).
  - `UserController` (`/users`): 14 endpoints (hồ sơ cá nhân, tạo/liệt kê/khóa/xóa mềm/khôi phục Host & Staff).
  - `AccommodationController` (`/accommodations`): 11 endpoints (CRUD, lọc, yêu thích, tìm theo GeoHash `nearby`, tìm theo từ khóa).
  - `RoomTypeController` (`/room-types`): 15 endpoints (CRUD loại phòng, cập nhật giá/giảm giá, quản lý phòng vật lý, tìm phòng trống).
  - `BookingController` (`/bookings`): 20 endpoints (đặt phòng, xem chi tiết, hủy, đổi trạng thái, lịch sử của Customer/Host và 12 API báo cáo/thống kê cho Host).
  - `ZaloPayController` (`/zalopay`): 2 endpoints (`create-order`, `callback`).
  - `ReviewController` (`/reviews`): 2 endpoints (`GET`, `POST`).
  - `LocationController` (`/locations`): 7 endpoints (`search`, `me`, `calculator`, `{locationId}`, `provinces`, `districts`, `all`).
  - `DeviceController` (`/devices`): 2 endpoints (`register`, `refresh`).
  - `FileUploadController` (`/file-upload`): 2 endpoints (`POST /cdn`, `POST /cdn/multiple`).
